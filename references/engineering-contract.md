# 通用工程契约：任务源、门禁证据与音频元数据

本记录描述本轮已实现的工程行为。镜头内容、动作模板和生成质量不属于这轮修改。

项目用 `.tunjing_project.json` 的 `active_batch` 指定唯一任务文件。路径必须相对于项目目录；有清单但路径无效时直接失败。没有清单的旧项目兼容读取 `批量任务.json`。门禁、终审、完整性签名、导出器和主运行器共用同一解析器。

Gate 4 按实际任务中的每一个 `prompt` 检查。Markdown 文档拆块检查与任务原文检查使用不同入口；代码围栏不能隐藏任务正文中的错误。格式规则要求 `summary`、`retention_analysis`、一个独立 `Camera:` 行和独立 `MOTION FLOOR:`。这只是文本检查，不能证明画面质量。

Gate 4/5 将绝对任务路径和原始文件 SHA-256 写入 `gate_sources`。任务文件内容或选择路径改变、旧记录没有绑定、复查失败时，原先的 Gate 4/5/6 失效。Gate 1–3 保留。实际提交前再次检查当前任务、状态和完整性令牌。签名计算失败时拒绝降级为裸哈希。

任务读取兼容没有 schema 的现有批量文件；显式未知 schema 被拒绝。正式提交前严格检查整数帧数、24 fps 时长、总帧数和 3–9 个有序图像引用。前三槽表示固定语义；扩展槽属于容量，未使用的连接必须断开。缺节点不能生成悬空连接。

音频来源独立于后期效果：

| 字段 | 原生音频 |
| --- | --- |
| audio_mode | H3_native_audio |
| audio_reference_required | false |
| ref_audios | [] |

逐镜字段优先于批次字段。显式冲突和错误类型直接报错。旧任务若保留参考音频文件名但没有明确模式，需要迁移，不能默默当成已绑定。元数据可描述 `H3_reference_audio`，但当前运行器没有对应路由实现，明确拒绝实际提交。普通生成音轨输出连接不属于参考音频输入。

完整性令牌长度为 16 个十六进制字符，绑定任务、状态和校验器源文件。随代码分发的固定 HMAC 密钥不构成访问控制边界；收据不会将任务 SHA 的前八位冒充提交令牌。必须在状态保存后使用当前令牌。

本轮保留原提示词与模型文件。项目提交器发现工作流模型与账本不同会明确停止，不会静默切换模型。旧内容模板、历史生成器、历史负载和画面质量仍需各自处理，不能凭这些工程检查声明全部修复。
